# 版本历史

整理自仓库发布提交，更早的版本细节见 [GitHub Releases](https://github.com/qiuyuxc/tunnel-manager/releases)。

## v2.6.0

- Android 原生界面统一为石墨与薄荷绿配色，重新整理登录、面板、按钮与浮动导航，保留深浅主题和轻量效果
- 更多菜单增加账户摘要和网络工具网格，可直接进入批量绑定，所有入口继续遵守角色与权限
- 隧道列表增加名称 / ID 搜索及带数量的状态筛选，区分正常、降级、离线、未连接和未知；详情中的路由与危险操作分区展示
- 全局新建、隧道列表和空状态共用创建弹层，提交区固定在底部；提交中防止重复操作，成功后保留运行命令、令牌与警告
- 监控列表增加真实七天可用率和单服务历史预览，详情支持切换服务查看响应趋势；抽样历史标明实际时间，未知、异常与缺测不伪装成正常曲线
- 添加 / 编辑服务、检查间隔和公开状态页移入独立弹层，保留草稿和提交反馈；移除服务与删除项目均需确认
- 关于页更新品牌头与本版说明，分别显示 App 版本、构建号及服务端版本；Android 安装包升级为 2.6.0（构建号 260）
- 服务端支持 PostgreSQL：设置 `DATABASE_URL` 即把存储换成数据库服务（SQLite 单文件仍是默认），表结构与迁移在启动时自动创建，`DATA_DIR` 单独指定上传与心跳目录；新增依赖 `github.com/jackc/pgx/v5`，部署与备份说明已同步
- 新增网页安装引导：面板还没有账户时只提供安装页面，可选择 SQLite 或 PostgreSQL（连接可先测试，支持主机名与 Unix socket 目录），再设置管理员用户名与密码；安装完成后服务自动重启进入登录页
- 不再生成默认管理员密码，也不再把它打印到日志（旧行为是 `admin123` 或随机密码打在启动横幅里）；`ADMIN_PASSWORD` 仍可在启动时直接创建账户，`DATABASE_URL` / `STORE_PATH` 仍优先于引导，容器部署不受影响

## v2.5.0

- 新增通行密钥（WebAuthn）：账户页可绑定指纹 / 面容 / 硬件安全密钥，登录页可直接用通行密钥免密登录，开启 2FA 的账户也能用它替代动态验证码
- 新增「禁用密码登录」：账户页可对单个账户关闭密码登录（需先绑定通行密钥），管理后台还能对整个面板强制只允许通行密钥；开启全局开关前要求至少一名启用的管理员已绑定通行密钥，避免面板被锁死
- 锁死也有退路：命令行 `-allow-password-login` 关闭面板开关并清除所有账户开关，管理员也可在用户列表一键「恢复密码登录」
- 依赖方默认按访问域名自动推导（沿用面板域名），反向代理或多域名场景可在「系统设置 → 通行密钥」填写依赖方 ID 与允许的来源，来源需与依赖方同域
- 绑定、删除、重命名通行密钥与登录成败都写入审计日志（新增「通行密钥」分类），失败登录记录来源 IP
- 破坏登录路径的操作都有前置校验：删除最后一个通行密钥、禁用密码登录、删除用户等
- Android App 同步支持通行密钥：登录页可直接用通行密钥登录，两步验证也能改用通行密钥，账户页可绑定 / 重命名 / 删除并开关密码登录；管理后台新增「审计」标签页（按用户、操作类型、时间范围筛选 + 分页 + 统计）与通行密钥设置
- 后端新增 `/.well-known/assetlinks.json`：App 通过数字资产链接校验域名归属，包名与签名 SHA-256 指纹在「系统设置 → 通行密钥」维护，默认预填仓库共用调试密钥的指纹
- 新增依赖：后端 `github.com/go-webauthn/webauthn`，前端 `@simplewebauthn/browser`，App `androidx.credentials`
- 新增登录限流：连续登录失败会触发滑动窗口限流，账号与来源 IP 分别计数，超限返回 `429` 与 `Retry-After`；覆盖密码登录、两步验证、通行密钥登录、注册、邮箱验证码、找回与重置密码等全部认证入口
- 常用网段自动放宽：登录成功会记住来源网段（IPv4 按 `/24`、IPv6 按 `/64` 聚合，90 天内有效，每账户最多 32 条），来自常用网段的失败额度按倍数放宽，陌生 IP 仍按基础额度
- 限流阈值与开关在「系统设置 → 登录保护」调整（账号 / IP 额度、时间窗口、熟悉网段倍数、触发时是否邮件通知管理员），也可整体关闭
- 概览图表可下钻：点击柱子查看当天的异常时间段，按目标分组列出起始时间、持续次数、状态与失败原因，并可跳转到对应监控详情；Android App 同样支持点击柱子
- 新增日志审计：管理后台新增「审计日志」标签页，记录登录与登出、用户与用户组、邀请码、系统设置（含 SMTP / OAuth / 加密密钥）、隧道与隧道规则、域名绑定、DNS 记录、监控项目与目标、IP 优选实验室等变更操作
- 支持按用户名模糊搜索、按操作类型筛选、按时间区间查询与分页浏览；顶部展示近 7 天操作数、失败次数、今日操作与活跃账号
- 登录成功、登录失败（含 2FA 失败）与退出登录都会留痕，失败登录记录来源 IP，便于发现暴力破解
- 日志按天保留：默认 90 天，可在「系统设置 → 审计日志」选择 30 / 90 / 180 / 365 天或永久保留，超期日志每小时自动清理
- 审计数据独立存储：追加写入 SQLite 的 `audit_logs` 表（迁移 v13），不参与配置保存时的全量重写，规模增长不影响面板性能
- 只读浏览不记录，避免噪声；`/api/admin/audit-logs` 与 `/api/admin/audit-logs/stats` 仅管理员可用

## v2.4.1

- 修复 App 登录状态失效后无限闪屏：会话过期时未清除本地凭据，登录页会立刻再次进入控制台、又拿到 401 弹回，循环往复；现在会清除会话、回到登录页并提示「登录状态已失效，请重新登录」
- App 中任何接口返回 `401` 都会交给控制台外壳统一处理，并保证只处理一次；`403` 仍按权限不足处理，不会误踢登录
- 会话有效期由 12 小时延长到 7 天
- 监控概览图表窗口由 12 小时改为近 7 天：每天一柱（当天峰值延迟 + 当天最差状态），没有数据的日子也占位，不再把某一天的流量压成一根超宽柱子
- 心跳历史保留期改为 8 天（每个目标上限 10080 条），以支撑 7 天窗口
- 概览接口新增 `bucket_sec` 与 `uptime`（`uptime_24h` 保留兼容）；客户端在字段缺失时按小时桶渲染，旧服务端配新客户端不会标错时间

- 概览图表固定返回 12 个小时桶（含空桶），不再为一小时画一根超宽柱子
