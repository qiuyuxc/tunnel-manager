# 多用户与管理后台

v2.0.0 起，Tunnel Manager 支持多用户注册与管理后台。所有数据存储在 SQLite（`data/tunnel-manager.db`），旧版 `config.json` 会在首次启动时自动导入：原管理员账号、OAuth 连接与监控项全部继承，原文件保留作备份。

## 注册策略（管理后台 → 系统设置）

| 开关 | 说明 |
| --- | --- |
| 开放注册 | 关闭后登录页不再显示注册入口 |
| 注册邮箱验证 | 需要先配置 SMTP；开启后注册需填写邮箱验证码 |
| 邀请码 | 关闭 / 选填 / 必填 三种模式，邀请码可绑定用户组 |

组合效果：

- 未配置邮件服务且邀请码关闭：填写邮箱密码即可直接注册
- 配置了邮件服务：注册需要邮箱验证码（验证码 10 分钟有效，60 秒内不可重发）
- 邀请码必填：还需填写有效的邀请码

## 用户与用户组

- 每个用户拥有独立的 Cloudflare 授权连接、隧道选择与监控项目，互相不可见
- 用户组决定权限：隧道管理、域名绑定、DNS 记录、服务监控、Cloudflare 授权
- 「默认用户组」为内置组，决定注册用户的初始权限；管理员不受权限限制
- 管理员可禁用、删除用户（重置密码会使该用户所有会话失效）

## 邀请码

在管理后台生成，可绑定用户组、限制使用次数与有效期。注册时填写有效的邀请码，账户即归入对应用户组。邀请码只在注册真正成功后才会计数，失败的注册不会消耗次数。

## 忘记密码

- 配置了 SMTP：登录页「忘记密码」通过注册邮箱接收重置验证码，自助完成重置
- 未配置 SMTP：请联系管理员在管理后台重置；管理员本人可使用命令行 `./tunnel-manager -set-password 新密码`

# 服务监控告警

在监控项目详情页的「告警设置」中开启：

1. 管理后台 → 邮件服务，填写 SMTP 信息并「发送测试邮件」确认通路
2. 监控详情 → 告警设置 → 打开开关，填写收件邮箱（多个用英文逗号分隔，留空发送到注册邮箱）

告警仅在状态**变化**时发送：服务从正常变为异常时收到一封告警，恢复时再收到一封恢复通知，持续异常不会重复发送。每次通知都记录在告警列表中，发送失败会注明原因。

## SMTP 配置说明

| 字段 | 说明 |
| --- | --- |
| 主机 | 例如 `smtp.qq.com`、`smtp.gmail.com` |
| 端口 | `465`（加密）或 `587`（STARTTLS） |
| 加密 | 选择「加密」即可，程序自动适配 465 隐式 TLS 与 587 STARTTLS |
| 用户名 / 密码 | 邮箱与授权码（QQ / 163 等需使用授权码而非登录密码） |
| 发件人 | 与登录邮箱一致即可 |

密码使用 `APP_ENCRYPTION_KEY` 加密存储。未设置该环境变量时会自动生成并保存在数据库中；也可以在管理后台手动设置（更换后需重启，且会使已保存的密文失效）。

## OAuth 客户端权限

在 Cloudflare 控制台创建 OAuth 客户端时，需要勾选以下权限，否则授权会得到零权限令牌：

- Account Settings : Read
- Cloudflare Tunnel : Edit
- Zone : Read
- DNS : Edit
- SSL and Certificates : Edit

OAuth 客户端的 Client ID / Secret / 回调地址也可以直接在管理后台的「Cloudflare 授权」卡片中配置，优先于环境变量。
