# 单机 IP 优选对照实验（临时原型）

问题：同一台 BGP 服务器上，将“一次 HTTP 响应延迟排序”改为“完整 HTTPS 耗时、多次成功率和适度网段分散”，能否改善下一批真实请求？

这是独立命令行脚本，不加载面板、不写 DNS、不使用云平台密钥。只依赖 Go 标准库。原型用于后续不同时段复测，确认方案后再吸收或删除；它不是生产功能。

## 运行

在仓库根目录：

```sh
go run backend/experiments/ip-selector-prototype/main.go -input /path/to/input.json -out /path/to/new-result.json
```

应当在需要测量的服务器上运行。在手机上运行得到的是手机所在网络的结果。

输入文件示例（替换为获准检测的真实域名、IP）：

```json
{
  "host": "probe.example.com",
  "sni": "probe.example.com",
  "path": "/ip-check.txt",
  "statuses": "200",
  "timeout_seconds": 3,
  "ip_targets": "203.0.113.0/24\n198.51.100.0/24",
  "current_ips": [],
  "extra_ips": []
}
```

示例地址为文档占位地址，不能用于真实效果测量。脚本支持单个 IPv4 或 `/24` 至 `/32` 网段；不接受更大的网段和 IP 范围。现有面板的候选格式更丰富，原型不替代其解析器。

默认每个网段随机取 2 个地址，并加入 `current_ips`（最近入选的 IP）和 `extra_ips`（指定对照），去重后最多 96 个。固定随机种子便于复现抽样；`-seed` 可更换样本与请求顺序。

## 对照方法

1. 每个候选测 5 次，每轮随机打乱顺序；每秒最多建立 2 条连接，同时最多 4 条。
2. 使用同一份观测冻结三组选择，每组最多 3 个 IP。
   - `old_http`：第一轮成功请求中，按握手后 HTTP 请求至状态行的耗时排序。
   - `full_timing_only`：第一轮成功请求中，按 TCP + TLS + HTTP 的完整耗时排序。
   - `repeated_diverse`：先比较成功比例，再比较成功请求完整耗时中位数及最慢耗时，选择时适度分散 `/24`。
3. 对三组选中 IP 的并集进行 3 轮新的复测；这部分数据不参与挑选。
4. 分别输出成功率、成功请求的完整耗时中位数、最慢请求及逐 IP 数据。

要与面板最新结果或此前的固定 IP 组对照，可以在输入 JSON 中添加 `comparison_groups`，例如 `{"panel_top3":["203.0.113.10","203.0.113.11","203.0.113.12"]}`。每组在实验前冻结，地址会加入候选和每轮独立复测，结果单独写入 `reference_evaluation`；不会用本轮训练结果替换这些组的成员。最多 8 组、每组 1–32 个不同地址，整体候选仍上限 96 个。这样可以在同一复测时段、同一计时口径下对比不同来源的选择，组间重合 IP 共用观测。

网段分散仅在同成功比例、耗时不超过 `max(最快中位数 × 1.5, 最快中位数 + 100ms)` 的候选间优先使用。数量不足时按稳定性和速度补齐，避免为了凑不同网段强塞慢地址。不同 `/24` 不代表不同运营商或独立路由。

## 测量口径

- 固定候选 IP，使用输入的 Host/SNI，保持证书校验与 TLS 1.2 最低版本。
- 使用与面板相同的 HTTP/1.1 GET、User-Agent 和 Connection: close；仅读取状态行，不下载正文、不跟随重定向。
- 新建 TCP/TLS 连接，不使用 TLS 会话缓存。排队和轮次间隔不计入耗时。
- TCP + TLS 共享一次超时，握手后 HTTP 使用新超时，与当前面板的分阶段超时一致。完整耗时可能超过单个超时值。
- HTTPS 失败也保留阶段、错误和耗时；失败请求不伪装为低延迟成功。
- JSON 每轮保存一次，输出文件必须不存在，避免覆盖之前的实验。
- 15 分钟自动截止，支持 Ctrl+C；中断结果有错误标记，不能当完成验证。

用 `-h` 查看请求速率、次数、间隔与候选数量的可调参数。

## 解释结果

本实验只能评价这台服务器的网络。即使新方法在复测中更好，也不能据此宣称电信、联通、移动全部改善。应结合多个时间段的重复实验及真实用户反馈。

最近入选的 IP 只作为候选种子；旧数据不计入评分。跨小时历史稳定性、连续两轮明显改善才替换、当前全网异常时保持 DNS 等行为尚未在此实验实现或验证。

首次实测已完成：52 个候选、281 次真实请求，新方法独立复测完整耗时中位数为 433.2ms，旧方法为 724.2ms；三组均 9/9 成功。只是单机单时段的小样本结果，网段分散本次未改变入选集合，不能据此推断三网效果。
